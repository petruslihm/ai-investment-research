# 평가 범위와 근거

이 저장소에서 확인할 수 있는 검사와 평가 범위입니다. 소프트웨어 동작, API 응답 품질, 투자 성과를 구분합니다.

## 공개 자료로 확인할 수 있는 것

| 증거 | 확인할 수 있는 내용 | 확인할 수 없는 내용 |
|---|---|---|
| [판단 처리 검사](../tests/test_submission_demo.py) | 판단 검증, 배분 제약, 미확정 값, 재개 조건, 화면 저장·복원 | 실제 API의 판단 품질이나 투자 수익률 |
| [분석 파이프라인 검사](../tests/test_v1_pipeline.py) | 신규 후보만 조사하는지, 조사 결과가 배분에 반영되는지, 저장한 화면을 복원하는지 | 실제 제공자의 모든 중단·장애 상황 |
| [Windows 실행기 검사](../tests/test_windows_launcher.py) | 실제 UI 시작, 필수 API 키 요구, 실행 시 자동 분석 차단 | 평가자의 API 권한·할당량과 모든 PC의 설치 성공 |
| [모델 평가 검사](../tests/test_evaluation_integrity.py) | 모델별 시간순 분리 지표, 평가 중복·표본 부족 처리 | 완전한 과거 재현과 전략의 초과수익 |

회귀 테스트에는 합성 입력과 외부 호출 대역을 사용합니다. 실제 API 응답·투자 성과나 비공개 프로그램의 운영 결과를 대신하지 않습니다. 커밋별 실행 결과는 [GitHub 자동 검증](https://github.com/petruslihm/ai-investment-research/actions/workflows/ci.yml)에서 확인할 수 있습니다.

## 머신러닝 지표의 해석

두 번째의 배치 회귀 지표는 모델별 **단일 시간순 분리 MAE**입니다. 해당 모델의 평가 입력을 사용하고, 학습·평가 중복이나 예측 기간에 필요한 날짜 간격이 부족하면 지표를 남기지 않습니다.

순위 모델은 적절한 순위 평가가 구현되지 않은 부분을 평가 불가로 표시합니다. 과거의 공유 `walkforward_mae`를 여러 모델의 성능으로 사용하지 않으며, 서로 다른 시점·평가 구간의 모델을 단순 개선율로 비교하지 않습니다.

전략 평가에는 현재 universe 선택, 과거 원문·모델 상태의 보존, 거래비용 반영 등 별도 검증이 필요합니다.

## 다음 비교 계획

같은 후보·계좌·판단 시각을 고정하고, 이후 실제 API 출력과 결과를 보존하는 전향적 비교가 필요합니다. 현재 입력으로 과거 AI 판단을 새로 만들어 당시 결과처럼 사용하지 않습니다.

| 질문 | 측정할 항목 |
|---|---|
| 수동 작업이 줄었는가 | 같은 과제의 사람 개입 횟수·소요 시간·수정 횟수 |
| 자동화가 완료되는가 | 최초 완료율·재시도율·불완전 응답률·단계별 지연 |
| 잘못된 입력과 출력을 잡는가 | 누락 계좌·변경된 판단 필드·잘못된 종목·단위의 검출과 오탐 |
| 근거가 사실과 맞는가 | 인용 주장과 원문 내용의 표본 대조 |
| 비용에 비해 유용한가 | 실제 사용량·청구액·사람의 결과 평가 |
| 투자 결과가 나아졌는가 | 같은 자본·기간·종목군·비용·현금 조건의 전향적 모의 운용 |
