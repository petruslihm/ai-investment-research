# 평가 범위와 근거

이 문서는 **두 번째 프로그램인 이 공개 저장소의 증거**를 기준으로 합니다. 소프트웨어 동작, API 응답 품질, 투자 성과는 서로 다른 검증 대상입니다.

## 공개 자료로 확인할 수 있는 것

| 증거 | 확인할 수 있는 내용 | 확인할 수 없는 내용 |
|---|---|---|
| 이 저장소의 코드·회귀 테스트 | 판단 검증, 배분 제약, 미확정 값, 저장·복원, 입력 고정과 재개 | 실제 API의 판단 품질이나 투자 수익률 |
| 실제 프로그램 실행기 | Python·패키지 준비와 연구 UI 실행, 필수 API 설정 안내 | 평가자의 API 권한·할당량과 모든 PC의 설치 성공 |
| 모델 평가 코드와 화면 | 모델별 시간순 분리 지표, 평가 중복·표본 부족 처리 | 완전한 과거 재현과 전략의 초과수익 |
| 첫 번째 공개 ZIP 스냅샷 | 미국·한국 스크리너, 수동 GPT 입력, 팩터·백테스트 구조 | 보존되지 않은 과거 Git 이력과 운영 성과 |
| 세 번째 개인 운용 경험 | 작성자가 다음 개발 방향을 정한 배경 | 이 공개 저장소에서 독립 재현할 수 있는 결과 |

회귀 테스트에는 합성 입력과 외부 호출 대역을 사용합니다. 이는 실제 API를 연결하는 사용자 실행과 별도이며, 테스트 통과를 실시간 분석 성공이나 수익률로 제시하지 않습니다. 실행한 명령과 결과는 [검증 기록](VALIDATION.md)에 있습니다.

## 세 프로그램의 증거를 섞지 않기

첫 번째는 [first-etf-radar](https://github.com/petruslihm/first-etf-radar), 두 번째는 이 저장소입니다. 세 번째는 작성자가 현재 사용하는 **비공개 ETF Radar**입니다.

세 번째의 과거 응답 횟수·토큰·실행 시간과 테스트 수를 두 번째의 성능으로 사용하지 않습니다. 비공개 운영 원문과 소스가 제공되지 않는 상태에서 외부 평가자가 확인할 수 있는 공개 증거처럼 연결하지 않습니다. 비공개 자료를 이 저장소로 복사하지도 않습니다.

로컬 코드에서 확인한 세 번째의 기능은 [개발 경위와 비교](DEVELOPMENT.md)에 기능 수준으로만 설명합니다. 같은 이름의 ETF Radar라도 첫 번째 수동 버전과 세 번째 자동화 버전은 구분합니다.

## 머신러닝 지표의 해석

두 번째의 배치 회귀 지표는 모델별 **단일 시간순 분리 MAE**입니다. 해당 모델의 평가 입력을 사용하고, 학습·평가 중복이나 예측 기간에 필요한 날짜 간격이 부족하면 지표를 남기지 않습니다.

순위 모델은 적절한 순위 평가가 구현되지 않은 부분을 평가 불가로 표시합니다. 과거의 공유 `walkforward_mae`를 여러 모델의 성능으로 사용하지 않으며, 서로 다른 시점·평가 구간의 모델을 단순 개선율로 비교하지 않습니다.

온라인 학습과 모델·예측 기간의 가중치 조정이 구현되어 있다는 사실도 투자 성과를 입증하지 않습니다. 현재 universe 선택, 과거 원문·모델 상태의 보존, 거래비용 반영 등은 별도 검증이 필요합니다.

## 다음 비교 계획

같은 후보·계좌·판단 시각을 고정하고, 이후 실제 API 출력과 결과를 보존하는 전향적 비교가 필요합니다. 현재 입력으로 과거 AI 판단을 새로 만들어 당시 결과처럼 사용하지 않습니다.

| 질문 | 측정할 항목 |
|---|---|
| 수동 작업이 줄었는가 | 같은 과제의 사람 개입 횟수·소요 시간·수정 횟수 |
| 자동화가 완료되는가 | 최초 완료율·재시도율·불완전 응답률·단계별 지연 |
| 잘못된 입력과 출력을 잡는가 | 누락 계좌·변경된 판단 필드·잘못된 종목·단위의 검출과 오탐 |
| 근거가 사실과 맞는가 | 인용 주장과 원문 내용의 표본 대조 |
| 비용에 비해 유용한가 | 실제 사용량·청구액·사람의 결과 평가 |
| 투자 결과가 나아졌는가 | 같은 자본·기간·종목군·비용·현금 조건의 전향적 모의 운용 |

이 비교를 수행하기 전까지 세 프로그램의 투자 우열이나 API 도입의 수익률 효과를 주장하지 않습니다.
