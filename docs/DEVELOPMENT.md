# 개발 경위와 세 프로그램의 차이

개발 순서는 **첫 번째 ETF Radar → 두 번째 AI Investment Research Assistant → 세 번째 개인 운용 ETF Radar**입니다. 이 저장소는 수동 입력과 결과 정리의 불편을 줄이기 위해 개발한 두 번째 프로그램입니다.

## 세 프로그램 비교

| 구분 | 첫 번째 | 두 번째 · 이 저장소 | 세 번째 |
|---|---|---|---|
| 공개 상태 | 공개 스냅샷 · `first-etf-radar` | 공개 · `ai-investment-research` | 비공개 · 현재 개인 운용 |
| 화면 | Streamlit | FastAPI/Jinja | Streamlit |
| 분석 범위 | 미국·한국 종목 | 미국 주식·BTC·USD 현금 | 미국 주식·BTC, ETF는 주로 비교 기준 |
| 후보 판단 | 기술 팩터·점수·리레이팅과 백테스트 | 여러 머신러닝 모델의 예측·보조 순위·배분 | 기존 스크리너의 기술신호 점수와 검증·최적화 보강 |
| AI 연결 | 프롬프트를 만들고 사용자가 GPT에 직접 입력 | Gemini 조사 후 GPT 검토, 코드 검증과 결과 저장 | GPT 조사·재점검·최종 판단·기록 변환의 자동 실행 |
| 학습·검증 | 팩터 가중치 최적화와 train/test 분리 | 여러 예측 모델과 온라인 학습, 모델별 지표 | 주간 최적화와 실제 GPT 판단 이후 결과를 이용하는 경험학습 코드 |
| 기록·재개 | 캐시·투자일지·포트폴리오 | 입력 고정, 단계별 기록, 동일 입력의 중단 재개, DuckDB 복원 | 실행 단위의 입력·응답 보존, 중단 재개와 최종 형식 검증 |

세 번째의 경험학습은 충분한 미래 검증을 통과한 경우에만 보정을 적용하도록 구현되어 있습니다. 현재 보정의 활성화 여부나 성과 개선은 공개 자료로 확인되지 않았습니다.

## 1. 첫 번째: 후보를 선별하고 GPT에 직접 질문

첫 번째 공개 저장소는 원본 ZIP의 소스를 보존한 스냅샷입니다. 공개 커밋 날짜는 과거 개발일을 뜻하지 않습니다.

## 2. 두 번째: API 리서치와 결과 추적

후보를 GPT에 옮기고 응답을 다시 정리하는 과정을 API로 연결하는 것이 출발점이었습니다. 자동화 이후에는 어떤 입력으로 판단했는지, 어느 단계에서 배분이 바뀌었는지, 중단된 분석을 같은 조건에서 이어갈 수 있는지가 중요해졌습니다. 입력 고정과 단계별 기록은 이 흐름을 추적하기 위한 설계입니다.

## 3. 세 번째: 기존 스크리너를 개인 운용에 맞게 발전

첫 번째 스크리너의 로직을 바탕으로 실제 사용 중 필요했던 자동 조사, 계좌 입력 검증, 실행 재개와 사후 평가를 보강했습니다. 기존 스크리너를 개인 운용에 맞게 발전시킨 별도 프로그램입니다.

## 작성자 역할과 AI 활용

- **작성자:** 메인 로직과 부가 기능 아이디어(freeze나 api 핑테스트 등)의 도출, API 전환 목표 설정, 실제 사용 경험에 따른 개발 방향 선택.
- **AI 도구:** 구현, 구조 검토, 오류 수정, 테스트와 문서 정리를 보조했습니다. 클로드AI, Codex, GPT, Cursor을 활용했습니다.
- **결과 범위:** 확인한 코드·검사만 근거로 설명합니다. 검증하지 않은 투자 성과나 업무시간 절감 수치를 제시하지 않습니다.
