# 개발 경위와 세 프로그램의 차이

개발 순서는 **첫 번째 ETF Radar → 두 번째 AI Investment Research Assistant → 세 번째 개인 운용 ETF Radar**입니다. 서로 다른 프로그램의 기능과 검증 기록을 구분합니다.

## 세 프로그램 비교

| 구분 | 첫 번째 | 두 번째 · 이 저장소 | 세 번째 |
|---|---|---|---|
| 공개 상태 | [first-etf-radar](https://github.com/petruslihm/first-etf-radar) | [ai-investment-research](https://github.com/petruslihm/ai-investment-research) | 작성자가 현재 사용하는 비공개 프로젝트 |
| 화면 | Streamlit | FastAPI/Jinja | Streamlit |
| 분석 범위 | 미국·한국 종목 | 미국 주식·BTC·USD 현금 | 미국 주식·BTC, ETF는 주로 비교 기준 |
| 후보 판단 | 기술 팩터·점수·리레이팅과 백테스트 | 여러 머신러닝 모델의 예측·보조 순위·배분 | 기존 스크리너의 기술신호 점수와 검증·최적화 보강 |
| AI 연결 | 프롬프트를 만들고 사용자가 GPT에 직접 입력 | Gemini 조사 후 GPT 검토, 코드 검증과 결과 저장 | GPT 조사·재점검·최종 판단·기록 변환의 자동 실행 |
| 학습·검증 | 팩터 가중치 최적화와 train/test 분리 | 5·10·20일 모델, 온라인 SGD, 가중치 조정, 모델별 지표 | 주간 최적화와 실제 GPT 판단 이후 결과를 이용하는 경험학습 코드 |
| 기록·재개 | 캐시·투자일지·포트폴리오 | 입력 고정, 단계별 기록, 동일 입력의 중단 재개, DuckDB 복원 | 실행 단위의 입력·응답 보존, 중단 재개와 최종 형식 검증 |

세 번째의 경험학습 코드는 충분한 미래 검증을 통과한 경우에만 보정을 적용하도록 되어 있습니다. 코드가 있다는 사실만으로 보정 모델이 현재 활성화됐거나 투자 성과를 개선했다고 주장하지 않습니다.

## 1. 첫 번째: 후보를 선별하고 GPT에 직접 질문

첫 번째 프로그램은 미국·한국 종목의 시세와 팩터를 이용해 후보를 압축하고, 목적별 GPT 프롬프트를 생성합니다. 사용자가 이를 복사해 GPT에 입력하는 흐름입니다. 팩터 가중치와 백테스트 기능도 이미 있었습니다.

초기 ZIP의 `app.py`에는 수동 복사 안내가 있으며, 세 번째 프로그램의 API 자동화나 workflow 6 검증을 첫 번째의 기능으로 설명하면 안 됩니다. 공개 저장소는 제공받은 ZIP의 소스를 보존한 스냅샷입니다. 공개 커밋 날짜를 과거 개발일로 해석하지 않습니다.

## 2. 두 번째: API 리서치와 결과 추적

반복 입력과 결과 정리의 불편을 줄이기 위해 별도로 개발한 프로그램이 이 저장소입니다. Quant 후보 선별 → Gemini 조사·배분 보정 → GPT 구조화 판단 → 코드 검증 → 화면 반영을 연결합니다.

Ridge·LightGBM·LSTM·온라인 SGD와 미국 주식용 LambdaRank가 구현되어 있습니다. 머신러닝이 세 번째에서 처음 도입됐다는 뜻은 아닙니다. 최종 판단은 허용된 종목·행동·단위·순위를 검사하고, 제약을 적용한 `effective`를 표시합니다. 중단 재개에는 고정한 입력 묶음과 같은 입력인지 확인하는 조건을 사용합니다.

평가자는 Windows 실행기로 실제 프로그램을 설치·실행하고, 필수 API를 연결해 분석합니다. 회귀 테스트의 가상 데이터는 소프트웨어 동작 검증용이며 실제 API 응답·투자 성과를 대신하지 않습니다.

## 3. 세 번째: 기존 스크리너를 개인 운용에 맞게 발전

작성자는 첫 번째 스크리너의 로직을 바탕으로 자동 조사, 계좌 입력 검증, 실행 재개와 사후 평가를 보강한 세 번째 프로그램을 현재 개인적으로 사용합니다. **세 번째 저장소는 비공개입니다.**

로컬 코드에서 미국 주식과 BTC의 처리 분리, 주간 최적화, GPT 자동 조사와 최종 형식 검증, 미래 데이터에 기반한 경험학습 코드를 확인했습니다. 이 기능을 두 번째 저장소에서 구현한 것처럼 설명하지 않으며, 비공개 소스·계좌·응답·운영 기록은 공개본에 옮기지 않습니다.

작성자의 사용 경험은 개발 방향을 선택한 근거입니다. 세 프로그램을 동일 기간·종목·자본·거래비용으로 비교한 실험 결과는 아니므로 어느 쪽이 더 높은 수익률을 냈다는 근거로 사용하지 않습니다.

## 설계의 선택과 한계

| 선택 | 목적 | 확인이 더 필요한 점 |
|---|---|---|
| 후보 선별·조사·최종 검토 분리 | 판단 변경의 위치를 추적 | 호출 비용과 단계별 실패 처리 |
| 구조화 결과와 배분 제약 | 종목·행동·단위의 범위 확인 | 근거 내용의 사실성과 투자 적합성 |
| 미확정 값을 그대로 보존 | 모르는 잔고를 0으로 오인하지 않음 | 입력이 충분하지 않으면 배분을 확정할 수 없음 |
| 입력 고정과 재개 조건 | 재시도에서 서로 다른 상태가 섞이지 않음 | 시세·계좌 변화가 있으면 다시 평가해야 함 |
| 실제 프로그램 자동 설치 | 평가자의 설치 부담 감소 | API 권한·할당량·비용은 별도로 필요 |

## 작성자 역할과 AI 활용

- **작성자:** 메인 로직과 부가 기능 아이디어(freeze나 api 핑테스트 등)의 도출, API 전환 목표 설정, 실제 사용 경험에 따른 개발 방향 선택.
- **AI 도구:** 구현, 구조 검토, 오류 수정, 테스트와 문서 정리를 보조했습니다. 클로드AI, Codex, GPT, Cursor을 활용했습니다.
- **결과 범위:** 확인한 코드·검사만 근거로 설명합니다. 검증하지 않은 투자 성과나 업무시간 절감 수치를 제시하지 않습니다.
